## P0 — Bugs & risques critiques

### P0.1 — L'écran se verrouille pendant l'écoute → session tuée
**Symptôme :** l'utilisateur SLA ne touche PAS l'écran pendant que les autres parlent. Au bout du
délai iOS de verrouillage auto, l'app passe en arrière-plan : AVAudioEngine coupé, STT mort,
conversation perdue. C'est LE scénario d'usage principal qui casse.
**Constat :** aucune occurrence de `isIdleTimerDisabled` dans le projet ; pas d'`UIBackgroundModes`.
**Fix :** dans WAV, `UIApplication.shared.isIdleTimerDisabled = true` quand l'écoute démarre
(handler `startNativeSTT` + `micStatusUpdate listening:true`), `false` à l'arrêt. Simple et suffisant
pour l'usage réel (l'app reste au premier plan, écran allumé).
**Option complémentaire (décision produit) :** `UIBackgroundModes: [audio]` dans `project.yml` pour
survivre à un passage en arrière-plan — attention justification App Review.
**Effort : S** (idle timer) / M (background mode).

### P0.2 — Tours de parole JETÉS pendant que Talkie parle
**Symptôme :** pendant la lecture TTS d'une réponse, si l'interlocuteur parle (très fréquent :
il réagit à la réponse), le final arrive avec `isSpeaking === true` et est **silencieusement
détruit** → trous dans `state.history` → suggestions suivantes hors-sujet.
**Constat :** WEB `window._nativeTranscript = function(json) { if (!isListening || isSpeaking) return; … }`
(idem `_nativeTranscriptInterim`). Note : en natif, le moteur est en général STOPPÉ pendant le TTS
(stop/start autour de `speakSuggestion`), mais les finals en vol au moment du stop + le cas
fallback Web Speech tombent dans ce guard.
**Fix :** au lieu de `return`, bufferiser : `_pendingTurns.push(turn)` quand `isSpeaking`, et au
retour d'écoute (`resumeListeningAfterTTS` / `hideTTSOverlay`) rejouer les tours bufferisés dans
`addToHistory` (sans régénérer de suggestions pour chaque, seulement le dernier).
**Effort : S.**

### P0.3 — Logging de debug expédié en prod (TestFlight build 21)
**Symptôme :** `dbg()` (SCM) fait `print()` de CHAQUE résultat volatile (texte transcrit inclus) ;
le pont `debugLog` (WEB→WAV) imprime toute la console JS ; `[STT] TURN speaker=… « texte »`.
Transcriptions de conversations privées dans les logs système d'un build distribué = problème
de confidentialité + bruit + coût CPU marginal.
**Fix :** gater : `#if DEBUG` autour du corps de `dbg()` et du handler `debugLog` ; supprimer le
log par-résultat volatile (garder uniquement transitions d'état). Retirer l'override console JS
ou le conditionner à un flag `state.devMode`.
**Effort : S.**

### P0.4 — Appel téléphonique pendant une session native : pas de reprise
**Symptôme :** un appel entrant coupe l'AVAudioEngine ; à la fin de l'appel l'écoute ne repart
pas seule (l'utilisateur doit re-taper — pénible avec une motricité réduite).
**Constat :** `CallModeManager.onCallModeChanged` notifie le JS, mais aucun chemin ne rappelle
`startNativeSTT` à la sortie d'appel quand `isListening` était vrai.
**Fix :** dans WEB `_callModeChanged(false)` : si `isListening || wasListeningBeforeCall`,
relancer `startListening()` après ~1 s (le temps que la session audio se libère).
**Effort : S.**

## P1 — Optimisations techniques (illogique / sous-optimal)

### P1.1 — Stop/start complet du moteur à CHAQUE réponse prononcée
**Symptôme :** ~1 s de « rechargement » après chaque phrase dite (le cycle le plus fréquent de
l'app). `speakSuggestion` → `stopListening()` (détruit analyzer+engine+modèle chargé) → TTS →
`startListening()` (retélécharge la config, `SpeechAnalyzer.start`, réinstalle le tap…).
**Fix (le plus rentable de tout l'audit) :** mode « pause » dans SCM : pendant le TTS, garder
analyzer/engine vivants et simplement **cesser de yield** les buffers (flag `suspended` testé dans
le tap), vider le ring, ignorer les résultats. `pause()`/`resume()` exposés via un nouveau message
(`pauseNativeSTT`/`resumeNativeSTT`) appelés par `speakSuggestion`/`_finishTtsJob` au lieu de
stop/stopListening. Attention : ne pas nourrir l'analyzer avec le son du TTS (l'engine capte le
haut-parleur) — d'où la coupure du yield, pas seulement du traitement.
**Effort : M.** Gain UX majeur (conversation fluide) + moins de churn mémoire.

### P1.2 — Diarisation : re-calcul complet 16 s toutes les 2 s, en continu
**Symptôme :** `performCompleteDiarization` (segmentation pyannote + embeddings wespeaker) sur
16 s d'audio toutes les 2 s, même dans le silence total → CPU/ANE/batterie en continu. Un
utilisateur SLA laisse l'écoute allumée des heures.
**Fix :**
1. **Gating par activité** : ne lancer le tick que si du volatile STT a été reçu dans les
   dernières ~4 s (le transcriber fait déjà VAD de fait). Silence → zéro diarisation.
2. En mode 1-à-1 **sans** table : réduire la cadence (tick 4 s) voire fenêtre 10 s.
3. `pcmRing` : remplacer `Array(pcmRing.suffix())` + `removeFirst` (O(n), ~1 Mo copié/tick)
   par un vrai ring buffer indexé (ou au minimum `ContiguousArray` + fenêtrage par index).
**Effort : M.**

### P1.3 — Premier tour de parole sans locuteur (et jamais réattribué)
**Symptôme :** la 1ʳᵉ phrase arrive souvent avant le 1er passage de diarisation → `fuseSpeaker`
renvoie `""` → tour historisé sans speaker, définitivement.
**Fix :** réattribution rétroactive : conserver les N derniers tours `{start,end,speakerId:""}`
côté SCM ; après chaque `runDiarizationOnce`, re-fuser ceux encore vides et notifier le JS
(`_nativeTurnSpeakerUpdate(turnId, speakerId)`) pour patcher l'entrée d'historique.
**Effort : M.**

### P1.4 — Watchdog de finalisation fixe (1,1 s) : coupe les parleurs lents
**Symptôme :** `silenceBeforeFinalize = 1.1` : un interlocuteur âgé/hésitant qui pause 1,5 s
en milieu de phrase voit sa phrase coupée en deux → deux tours, deux générations de suggestions.
**Fix :** réglage « patience » (1,0 / 1,5 / 2,2 s) dans les réglages Accessibilité, transmis via
`startNativeSTT`. Défaut 1,4 s.
**Effort : S.**

### P1.5 — Tâches LLM d'arrière-plan incohérentes avec l'option Claude
**Symptôme :** `maybeExtractMemory` / `refreshStyleSummary` passent TOUJOURS par le modèle Apple
(qui refuse souvent → `Memory extraction failed`), même quand l'utilisateur a configuré Claude
pour les suggestions. Résultat : mémoire/style ne se remplissent jamais chez un utilisateur Claude.
**Fix :** router ces deux fonctions par le même sélecteur que `requestStructuredSuggestions`
(Claude si activé, sinon Apple) ; échec → silencieux (pas de console.warn en boucle).
**Effort : S.**

### P1.6 — `stop()` : finalisation détachée non annulée
**Symptôme :** SCM `stop()` lance `Task { try? await a?.finalizeAndFinishThroughEndOfInput() }`
sans le retenir : un stop/start rapide (toggle table, reprise après TTS) peut faire finaliser
l'ancien analyzer pendant que le nouveau démarre (contention modèle, résultats fantômes).
**Fix :** retenir la task, `await`-la (avec timeout court) au début de `start()`, ou
`cancelAndFinishNow()` à la place.
**Effort : S.**

## P2 — Features manquantes évidentes (usage AAC réel)

### P2.1 — Renommer un locuteur
« Locuteur 3 » n'est pas renommable (le picker sait ajouter/supprimer, pas renommer — grep
`renameSpeaker` : absent). Le plan UI le prévoyait. Tap sur le chip locuteur → sheet avec champ
nom + relation. Indispensable pour que le contexte LLM (« Marie (épouse) ») serve à quelque chose.
**Effort : S.**

### P2.2 — Éditer une suggestion avant de la prononcer
Les 3 réponses sont à prendre ou à laisser ; s'il manque un mot, l'utilisateur doit tout retaper
dans « Écrire ». Appui long sur une carte → ouvre `view-manual` pré-rempli avec le texte de la
carte. Deux lignes de JS, énorme gain.
**Effort : S.**

### P2.3 — Répéter la dernière phrase prononcée
Besoin AAC classique (« pardon, tu peux répéter ? »). Un bouton « re-dire » (icône speaker) dans
la bottom bar ou en appui long sur « Écrire », qui rejoue `state.history` dernier `isUser`.
**Effort : S.**

### P2.4 — Sauvegarde / restauration
Tout vit dans localStorage (profil, mémoire apprise, locuteurs, phrases rapides) + keychain.
Téléphone perdu = identité vocale et mémoire perdues. Export/import JSON via la feuille de
partage iOS (bouton dans Réglages), et/ou `NSUbiquitousKeyValueStore` pour le state (hors clés).
**Effort : M.**

### P2.5 — Garder l'écran éveillé = P0.1 (rappel produit)
Et afficher discrètement l'état (« Écoute active — l'écran restera allumé »).

### P2.7 — Mode appel : assumer la limite iOS, refondre l'UI (« clavier d'appel »)
> (Placé avant P2.6 dans le fichier — ordre de lecture sans importance, priorités en tête de doc.)
**Contexte technique (vérifié, non contournable) :** iOS n'expose l'audio d'un appel à aucune app
tierce — ni le downlink (la transcription d'appels d'iOS 18.1+ est réservée au système, ReplayKit
exclut l'audio d'appel), ni le micro pendant l'appel (session record tierce refusée,
`InsufficientPriority` — cf. commentaire dans `CallModeManager.swift`). Les suggestions
automatiques ne peuvent donc PAS fonctionner pendant un appel sur le même iPhone. Ce qui
fonctionne : parler dans l'appel via l'injection TTS iOS 18.2 (déjà en place). Seule config
d'écoute possible : appel sur un AUTRE appareil en haut-parleur → mode « Plusieurs voix ».

**Problème UX actuel :** en appel, l'écran garde la zone suggestions (vide/périmée) + un retry
d'écoute qui échoue en boucle avec toasts — frustrant, incompréhensible.

**Refonte proposée (`body.call-mode` pilote déjà le CSS) :**
1. **Remplacer la zone suggestions par des « Phrases d'appel »** : grille de grandes cartes
   (mêmes styles que les suggestions) — Allô ? / Oui / Non / Peux-tu répéter ? / Deux secondes,
   j'écris / Je te rappelle / Merci, au revoir. Liste dédiée éditable dans les réglages
   (séparée des quick phrases). Tap = injection TTS dans l'appel (chemin existant).
2. **« Écrire » en avant** + accès direct à l'historique pour re-dire une phrase.
3. **Listen chip → état « Appel en cours »** (icône téléphone, pas de waveform) ; tap = petite
   explication au lieu du retry automatique. Supprimer `scheduleCallModeListenRetry` (source de
   toasts d'échec) au profit d'un bouton explicite unique.
4. **Message pédagogique une fois par appel** : « iOS ne permet pas aux apps d'écouter l'appel.
   Vos phrases, elles, sont bien entendues par votre correspondant. » + astuce : « Appel sur le
   téléphone d'un proche en haut-parleur → activez Plusieurs voix. »
5. À la fin de l'appel : restaurer l'UI normale + reprise d'écoute auto (= P0.4).
**Effort : M.** (Idée à explorer plus tard, effort L : « ouvreurs » générés par l'IA sans écoute,
à partir du contexte/mémoire/heure — de la génération proactive, pas de la transcription.)

### P2.6 — Raccourci de démarrage rapide
App Intent / Siri Shortcut « Lance l'écoute Talkie » + activation auto de l'écoute à l'ouverture
(réglage opt-in « Écouter dès l'ouverture ») — réduit les taps pour une motricité réduite.
**Effort : M.**

## P3 — Dette technique (à planifier, pas urgent)

1. **Double implémentation des Réglages** (SET SwiftUI *et* `view-settings` HTML) synchronisées
   par `syncSettingsToJS` avec échappement manuel de chaînes — fragile, déjà source de bugs.
   Cible : une seule (garder la native, supprimer la web), ou générer la web depuis un schéma.
2. **Canal Swift→JS par concaténation de strings** (`runJavaScript("… '\(escaped)' …")`) éparpillé.
   Cible : un unique `postToJS(event: String, payload: Encodable)` qui `JSONEncoder`-ise et
   dispatch sur `window._talkieEvent(name, payload)`. Élimine toute la classe de bugs d'escaping.
3. **i18n** : les libellés ajoutés récemment sont des ternaires `currentLang === 'fr'` inline
   (mode table, toasts STT, labels chips) au lieu du dictionnaire `I18N`. Centraliser.
4. **Zéro test.** Les purs candidats : `consolidate()`/`cosineSim` (SCM), `fuseSpeaker`,
   `parseSuggestionLines`, `inferQuestionMark`, prune des locuteurs fantômes. Cible XCTest +
   un petit harnais node pour les fonctions JS pures (extraites dans un module testable).
5. **Legacy Web Speech** : tout le code kill/restart (`beginRecognition`, retries, PHRASE_END_MS)
   ne sert plus que de fallback rare (cible iOS 26 only). L'isoler dans une section clairement
   marquée, ou le supprimer après télémétrie confirmant qu'il ne s'exécute jamais.
6. **`_fluidToTalkie` non persisté** : après relance de l'app, S1/S2 repartent de zéro pendant
   que les speakers Talkie existent → risque de doublons (mitigé par le prune au démarrage).
   Persister le mapping OU repartir aussi de zéro côté speakers auto.
7. **`bingo.png`** traîne à la racine du repo (untracked) — supprimer ou déplacer.
8. **`PrivacyInfo.xcprivacy`** : vérifier que les reasons couvrent SpeechTranscriber + micro
   (nouvelle API) avant la prochaine soumission App Store.

## Vérifié sain (ne pas « corriger »)

- **Clés API** : `save()` supprime `elApiKey` ET `claudeApiKey` avant localStorage ; stockage
  keychain natif (`KeychainHelper`) + migration localStorage→keychain en place. ✔
- **Consentements** (IA, ElevenLabs, clonage) : flux explicites, persistés, testés. ✔
- **Fallback STT** : watchdog 8 s → bascule Web Speech automatique ; l'écoute ne reste jamais
  silencieusement morte. ✔
- **Fusion transcription/diarisation** : horloge partagée par `bufferStartTime` (CMTime 16 kHz),
  fusion par recouvrement majoritaire — architecture saine. ✔
- **Converter audio** : `.noDataNow` (streaming-safe) partout. ✔
- **`prefers-reduced-motion`**, cibles tactiles ≥ 44 px, contraste AA du nouveau thème. ✔
